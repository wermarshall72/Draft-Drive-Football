# Project Guidance

## Current Gameplay Direction
* The game is offline-first against local AI. Asynchronous player snapshots are a later goal.
* Matches are interactive: the user chooses each offensive play and one defensive scheme at the start of each defensive drive; that scheme remains active for the drive. Two perk exceptions: Read Keys (L4) shows the owner the rival's offensive hand while choosing a scheme, and Green Dog (L6) lets the owner swap the active scheme once per game after a rival 3rd/4th-down conversion. AI controls the side the user is not controlling.
* The defense call is secret from the offense. The human never sees the AI's call or its family: not on the field, the outcome strip ("<RIVAL> SET THEIR DEFENSE"; an AI Green Dog swap says only that the rival changed its defense), the hand (no STOPPED tag; the card tooltip ends "Rival call: secret"), the Play Log, or replays. Perk callouts and Play Log entries whose firing depends on the AI's call are hidden (the perks still work): the AI's call-keyed defensive perks, the human's Silent Count and Screen Wall's standing effect, and the coach perks Coverage, Pressure / Blitz, and Run Stop; `scheme_keyed_defense` in `football_perk_context.py` classifies them, and Hot Route's callout reads "SWAPPED A CARD". The human still sees their own call, its "STOPS X" label, every stop the AI runs into, and the scouting line. Read Keys (L4) is the deliberate exception: it still shows its owner the rival's offensive hand.
* Offense previews and AI offense are blind: `calculate_blind_play_estimate` averages `calculate_match_play_estimate` over the defending team's possible calls, weighted by its whole owned defensive deck (family counts), and never reads the opposing `current_drive_defensive_scheme`. The human's "YDS LIVE" numbers (two-point tries included), card tooltips, and every AI offensive choice (Standard's perk bonus, Hard's play score, two-point card choice; fourth-down choices never read it) use it; preview notes keep only perks whose firing does not depend on the call. Resolution and engine perk effects (the AI's own Hot Route included) use the real call; AI defense (scheme choice, Green Dog) is unchanged.
* Offensive plays and defensive schemes are selected from separate run-owned decks. The opening playbook contains the six basic actions per side; match hands are dealt independently, played cards cycle through discard/draw, and only the human's current hand is shown as selectable in the desktop match screen. The shop can add catalog cards or permanently remove a selected owned copy, while preserving a four-card minimum per deck.
* The pre-match shop's Depth Chart and Playbook reviews are read-only except for the explicit pending-removal flow. Keep those screens tied to the current run's roster, coach assignment, upgrades, and owned deck copies.
* The first coach-upgrade catalog is available from the shop before week 4 (after week 3); its two coach slots retain their existing 4 AP and 6 AP unlock costs. Named coach upgrades are unique for the run, distinct from draft coaches and player-upgrade history, and affect only the human team's match snapshot.
* Coach-upgrade power bonuses apply after existing player, coach, partnership, fatigue, and scheme calculations; matching bonuses add and cap at +20%. Volatility reductions add to a 30% cap, effective stamina bonuses add to +0.30 and cap each player's effective stamina at 1.0, family-yardage changes add and clamp to a 0.50-1.50 multiplier, and relative clock changes add and clamp to 0.75-1.25. For yardage, apply the net offense bonus minus matching defense reduction in the beneficial direction: positive gains use `1 + delta`, negative gains use `1 - delta`, and zero is unchanged. Apply this multiplier after additive perks and before the existing -5 to 25 yard result cap; incomplete passes and interceptions remain zero, and play risks are unchanged. Clock percentages round half-up to whole seconds with a one-second minimum; incomplete passes remain 5 seconds and conversions and special teams keep their existing clock rules. Ordinary coach effects last for the run; Bye Week is a one-time scheduled-game skip.
* The two +1 future-shop AP upgrades stack to +2 AP, apply only to later shops in the same run, and are not offered in the championship shop (week 13) because no later shop remains. Bye Week is Very Rare, costs 6 AP, ends the current shop, and skips that regular-season week's game without a result or record change; it is never offered in a playoff shop. Skipping week 10 ends the regular season and seeds the bracket without creating a match.
* Player-facing text says a defense call "stops" a kind of play: "STOPS DEEP PASS" on scheme cards and the outcome strip, "stopped"/"STOPPED" for a countered play (perk and coach wording too), and "defense call" where a label or prompt names a defensive scheme. Never show "counters"/"countered"; code names (`counters`, `scheme_matches_play`, enums) stay unchanged. The idea everywhere: your defense picks one kind of play to stop; if the offense calls that kind, it's stopped.
* Player-facing text calls the schedule slot a week (`WEEK 07`, `WK7`, "shop before week 8"); the code keeps `game_number` for it, and "game" in the UI means a single match ("1/game" perk limits, "N GAMES PLAYED", "NO GAME PLAYED").
* Drives use football downs and first downs, not a fixed number of plays.
* The roster has exactly eight player positions: QB, RB, WR, O-line, D-line, linebackers, cornerbacks, and safeties. Coach and special teams are separate from those player slots.
* Three losses end a run immediately. Surviving week 10 seeds an eight-team, single-elimination bracket (`src/engine/football_playoffs.py`): the human is seeded by regular-season losses (0 -> #1, 1 -> #2, 2 -> #3), pairings are 1v8, 4v5, 3v6, 2v7, and the other seven seeds are catalog AI teams drawn from the regular-season rivals the human played plus the run's ten reserve teams, so the field mixes rematches and new teams. Weeks 11-13 (the playoff rounds) are the quarterfinal, semifinal, and championship, each preceded by the normal shop; a playoff loss ends the run (ELIMINATED) and the title ends it (CHAMPION). Each round's rival gets +0.25 player power per round and one extra deck card per round beyond the difficulty cap (provisional). AI-vs-AI games are decided by the bracket's own RNG (seeded from the AI seed) once the human's game in that round is recorded. Wins, losses, and the season history stay regular-season only. A Bye Week may skip a regular-season week without adding a win or loss.
* Local AI opponents have cosmetic identities from the 100-team catalog in `src/engine/football_ai_teams.py` (reviewed in [docs/ai-team-names.md](docs/ai-team-names.md)): a plural mascot name, a 2-4 letter abbreviation, and primary/secondary `COLOR_CHOICES` ids. Each run draws 20 distinct teams once at the start from its own AI-seed stream: ten regular-season rivals in schedule order (week n always faces team n, even if a Bye Week skips it) and ten playoff reserves. Teams named like the human's team or sharing its profile primary color are never drawn. Rosters, coaches, and decks are still generated per game, so a playoff rematch never repeats a regular-season deck (playoff decks always carry extra cards). Keep team ids stable; saves store them.
* The desktop app is the main experience; Steam and a possible Apple app are long-term goals.
* `src/engine/football_controller.py` exposes `FootballGameController` and immutable state views for the interactive flow; keep UI and framework dependencies out of this module.
* The playable play/scheme catalog is organized into the six `FootballCardFamily` values: RB Run, Screen Pass, Play-Action Pass, Short Pass, Medium Pass, and Deep Pass. Named cards in a family share contributors, counters, coach/partnership interactions, and resolution rules; offensive variants differ only by name/flavor, base yardage, and clock duration. All play/scheme shop cards are Common. Keep card IDs stable and preserve each owned copy's `card_id` and `copy_id` through hand, AI, simulation, and event history. Ground and Pound triggers on the first RB Run-family attempt per offensive drive; Run Stop triggers only on an RB Run-family play against the RB Run-family scheme. Ball-Hawk adds 10 interception-return yards and scores a defensive touchdown immediately if the return reaches the opponent's goal line. Option / Spread adds 1 yard to a non-turnover run or completed pass when the offense goes for it on fourth down; this value is provisional for later balance work. Match actions are limited to the current hand, with an empty-hand basic-action fallback.
* Specialist player perks are active for both teams ([docs/player-perks-proposal.md](docs/player-perks-proposal.md) is the approved spec, with its recorded decisions). Each perk is a typed kind with values in `src/engine/football_player_catalog.py`; wording (card line ≤60 characters, full rules, callouts, preview notes) comes only from `src/ui/football_player_perks.py`. Perk history (snap index, uses, charges) is rebuilt from match events by `src/engine/football_perk_context.py`, never stored on the simulator; uses spent on a challenged play are not refunded. Estimate perks live in `calculate_match_play_estimate`; resolution uses it with the real call, while previews and AI offense use the blind estimate built from it (above). Resolution order: estimate inputs, roll, completion reroll, result swaps (offense first, at most one), yards (big gain, run floor, defensive caps win), spot (offense, then the defense has the last word; each side at most once), clock, then cards. Perk draws have no hand ceiling. Every fired perk is recorded as a `FootballPerkActivation` on its event.
* AI drafting is a seeded weighted choice at every difficulty that favors partners of already-drafted players and perks fitting the coach pair's deck families; drafts and rosters stay deterministic from their seeds. Bait & Jump's payoff and Keep Read are each limited to once per half (overtime is one half); the AI goes for two when it holds a Keep Read unused this half and a Play-Action card.
* Regulation uses two 900-second periods. Halftime ends the drive (drive-scoped perk effects and charges end, per-half uses refresh, hands are redealt) and period 2 opens with a kickoff by the team that received the opening kickoff (`FootballMatchState.opening_possession`); a touchdown conversion pending at the end of the half still resolves first. Offensive card durations are read from their definitions; incomplete passes use five seconds, turnovers use the played card's duration, punts and kickoffs use ten seconds, field goals use five seconds, conversions are untimed, and other actions without an assigned duration do not consume clock. A two-point attempt uses a legal card in the acting team's current hand (or the basic-run fallback when empty) and cycles that card. After a defensive conversion return, the original touchdown team kicks. Blocked punts and field goals resolve automatic recovery/return outcomes, including a possible defensive return touchdown and conversion. Kicking-team recoveries are modeled at or behind the original line of scrimmage; because they occur on fourth down and no forward recovery is simulated, they are turnovers on downs at the mirrored recovery spot, not automatic first downs.
* A match tied after regulation goes to sudden-death overtime: 300-second periods, each starting with a randomly chosen possession at the 25-yard line and no kickoff. The first score in overtime ends the match once any touchdown conversion is resolved; a period that expires tied starts another overtime period.
* Each deal gives every team three offensive cards and two defensive schemes; the offensive and defensive hands are independent and never share space. Every played card (plays, schemes, and bonus cards) goes to discard and replaces itself from its own draw pile, which reshuffles the discard pile when empty. Challenge keeps its own replacement rules. A bonus card with "Draw" in its effect adds one extra card on top of its replacement: Offensive Draw and Offensive Draw & Discard add an offensive card; Defensive Draw and Defensive Draw & Discard add a defensive scheme. Opponent Discard only replaces itself. A bonus card never draws its own copy back as its replacement or extra card, and a draw with nothing drawable is a no-op. There is no hand-size cap during a drive. When a drive ends (score, turnover, punt, field goal attempt, turnover on downs, safety, or a period ending; a two-point try belongs to its scoring drive), the offense's offensive hand returns to three and the defense's defensive hand to two: extras are discarded at random with that deck's own RNG, and short hands draw with the existing draw/reshuffle helpers (nothing if nothing is drawable). Draw bonus cards and card-keeping perks therefore help for the rest of that drive only. All four decks are reshuffled and redealt to three and two at halftime and again at the start of overtime.
* Remove One Card is once per shop visit: after it is used, Next Day rerolls and slot unlocks do not offer it again until the next visit.
* Next Day costs 1 AP and rerolls every unlocked shop offer. It clears same-day purchase exclusions for player upgrades and plays/schemes; coach upgrades stay run-unique, Remove One Card stays once per visit, and Next Day is blocked while a card removal is pending.

## Saving
* Exactly one active run is saved, as `run.json` (plus `run.backup.json`, the previous good save) beside `profile.json` in the OS app-data folder named by `APP_DATA_NAME` in `src/persistence/paths.py` (`DDF_DATA_DIR` overrides it). The desktop saves after every successful decision, on Return to Menu, and on quit; ended (FIRED/ELIMINATED/CHAMPION) and quit runs delete the save.
* Every file the game writes (profile, run save, the terminal client's legacy `cfb_battler.db` from `legacy_database_path`) lives in the app-data folder; nothing writes inside the install or project folder, which Steam and Mac App Store installs make read-only. Resolve these paths when used, never at import.
* `settings.json` (music and sound-effect volumes, `src/audio_settings.py`) sits beside `profile.json` and is not part of the run save (no schema version or migration); a missing or damaged file falls back to the defaults (bad values clamp to 0-100 in steps of 5) and is never deleted, only rewritten by the next volume change.
* Engine objects own their format via `to_save_data`/`from_save_data`: stable IDs and enum `.value`s only, exact `random.Random` states, and every attribute that affects play (audit new `__init__` attributes and save or document them). A restored run must continue identically to an uninterrupted one. Unknown IDs raise `UnsupportedSave`.
* The file is a versioned, checksummed JSON envelope. Any payload change bumps `CURRENT_SCHEMA_VERSION` and adds a dict-only `N -> N+1` step to `src/persistence/migrations.py` with a test. Never load or overwrite a save from a newer version without asking; never delete a damaged or unloadable save (move it aside). Never use pickle, and never store absolute paths, user/machine names, or local times.
* `src/persistence/` does all file I/O and imports no pygame; tests must use temporary folders (see `tests/conftest.py`).

The existing auto-battler engine, controller, shop, and snapshot code are legacy reference implementations, not gameplay compatibility requirements. Reuse them only where they fit the current direction. Do not infer redesigned mechanics from their old behavior.

See [FUTURE_WORK.md](FUTURE_WORK.md) for deferred redesign work and open decisions; update it when work is completed or the design changes.

## Development and Tests
* Supported Python version: 3.10 or newer.
* Install the test dependency with `python -m pip install -e ".[test]"`.
* Run the automated tests with `python -m pytest`.
* Tests use temporary SQLite databases and never access the local game database.
